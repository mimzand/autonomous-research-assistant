# Security model

This document covers what the desktop app protects, how it does so, and which test proves
each control. Tests named `e2e-packaged` run against the packaged app; see
[release.md](release.md#4-test-the-packaged-app).

## Assets and threats

| Asset                                                | Main threats                                                                                                      |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| The user's computer (files, programs, local network) | Web content or a model answer that tricks the app into running code, deleting files or reaching internal services |
| The research database (tasks, sources, reports)      | Tampering, loss, leaking it through logs                                                                          |
| The user's prompts and documents                     | Being sent to a cloud service                                                                                     |
| The integrity of reports                             | Prompt injection that plants false claims or fake citations                                                       |

Everything the app reads from the web, from search results and from the model is
treated as **untrusted**.

**Accepted risk:** the `GrantFileProtocolExtraPrivileges` fuse stays **on**, because the
renderer is loaded from `file://`; with the fuse off, the window does not load. The
compensating controls are `connect-src 'none'`, navigation locked to `index.html` and
IPC accepting only that page. Removing the fuse requires serving the renderer from a
custom `app://` protocol, which is a possible future change.

## Agent

| Control                                                                                                                                                                                                                                                                                                                                                                             | Where                                                         | Verified by                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Explicit tool permissions:** every tool declares network, filesystem and effects. A tool with external effects must require approval (otherwise registration fails). Calls without an approval id are refused.                                                                                                                                                                    | `packages/tools/src/{tool,registry}.ts`                       | `registry.test.ts`                                                                                    |
| **User approval for write actions:** the research workflow never approves itself and refuses tools with `requiresApproval` or external effects (`tool.refused`). The only writes are to the app's own database, plus the backup file, whose path the user chooses in a save dialog.                                                                                                 | `research/workflow.ts`, `main/index.ts`                       | `lifecycle.test.ts` (approval guard)                                                                  |
| **No shell execution:** no `child_process`, `spawn`, `exec`, `fork` or `worker_threads` in shipped code.                                                                                                                                                                                                                                                                            | —                                                             | `security-guards.test.ts`                                                                             |
| **No arbitrary file deletion:** the only delete removes the backup's own temporary file after a failed backup. Local files reach the tools only through a native file picker.                                                                                                                                                                                                       | `storage/src/inspect.ts`, `research-tools.ts`                 | `security-guards.test.ts`                                                                             |
| **No dynamic code evaluation:** no `eval`, `new Function` or `vm`.                                                                                                                                                                                                                                                                                                                  | —                                                             | `security-guards.test.ts`                                                                             |
| **No model downloads:** the app never calls Ollama's pull, push, create or delete endpoints. It only shows the `ollama pull` command.                                                                                                                                                                                                                                               | `model-provider`                                              | `security-guards.test.ts`, `e2e-packaged` (request log)                                               |
| **Untrusted web content:** page text, page titles and claims derived from pages appear in prompts only inside `<<<UNTRUSTED_WEB_CONTENT … UNTRUSTED_WEB_CONTENT>>>` blocks. Fence markers inside the content are neutralised, and invisible or bidi control characters are stripped. The system prompt says the content is data. Hidden HTML is dropped during extraction.          | `tools/src/web/untrusted.ts`, `research/prompts.ts`           | `web.test.ts`, `workflow.test.ts`                                                                     |
| **Prompt-injection resistance by design:** model output is JSON validated with Zod. Tools are called by fixed workflow code, never by the model. Every claim needs an exact quote found in the stored source. Evidence ids and citations are assigned and rendered by the app, never by the model. Unsupported paragraphs are removed.                                              | `research/*`                                                  | `workflow.test.ts` (injected instruction has no effect; invented evidence ids and quotes are dropped) |
| **SSRF:** fetching allows only public http(s) addresses. DNS is resolved and every address is checked (no private, loopback, link-local or metadata addresses, including after redirects). Ports and redirect count are limited, downloads are size-capped and time-limited, and SearXNG results are re-checked. The only private address contacted is the user-configured SearXNG. | `tools/src/web/{url,ip-policy,http-client}.ts`                | `url.test.ts`, `http-client.test.ts`, `web.test.ts`                                                   |
| **Redaction:** the execution log (message and data), step errors, task errors and the main-process console are redacted. This covers URL credentials, secret query parameters (`token`, `key`, `code`, `signature`, …), bearer/basic tokens, `password=`-style pairs, well-known API key formats, e-mail addresses, and the user name in `C:\Users\…` or `/home/…` paths.           | `shared/src/redact.ts`, `storage` repositories, `main/log.ts` | `redact.test.ts`, `storage/lifecycle.test.ts`, `startup.test.ts`                                      |
| **No cloud inference:** Ollama is the only model provider. The renderer cannot reach the network.                                                                                                                                                                                                                                                                                   | —                                                             | `renderer-isolation.test.ts`, `e2e-packaged`                                                          |

## Reporting a problem

Treat anything that lets web content or a model answer do more than "be text in a
report" as a security bug.
