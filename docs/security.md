# Security model

This document covers what the desktop app protects, how it does so, and which test proves
each control. `smoke:packaged` (`apps/desktop/scripts/smoke-packaged.mjs`) runs against
the packaged executable; see [release.md](release.md#4-test-the-packaged-app).

## Assets and threats

| Asset                                                | Main threats                                                                                                      |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| The user's computer (files, programs, local network) | Web content or a model answer that tricks the app into running code, deleting files or reaching internal services |
| The research database (tasks, sources, reports)      | Tampering, loss, leaking it through logs                                                                          |
| The user's prompts and documents                     | Being sent to a cloud service                                                                                     |
| The integrity of reports                             | Prompt injection that plants false claims or fake citations                                                       |

Everything the app reads from the web, from search results and from the model is
treated as **untrusted**.

**Process model (Phase 8):** the agent (research workflow, Chat, tools, SQLite,
Settings) runs in its own process, an Electron utility process the app starts from the
fixed entry `out/agent/main.js` (not `ELECTRON_RUN_AS_NODE`: the fuse stays off). It
listens on `127.0.0.1` only, accepts only clients that present the token from its
owner-only state file in the user-data folder, and is stopped on quit. Electron main
keeps the windows, dialogs and `safeStorage`; it opens no database. Details, the spawn
allow-list and the protocol rules: [agent-process-security.md](agent-process-security.md).

**Accepted risk:** the `GrantFileProtocolExtraPrivileges` fuse stays **on**, because the
renderer is loaded from `file://`; with the fuse off, the window does not load. The
compensating controls are `connect-src 'none'`, navigation locked to `index.html` and
IPC accepting only that page. Removing the fuse requires serving the renderer from a
custom `app://` protocol, which is a possible future change.

## Agent

| Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Where                                                                                      | Verified by                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| **Explicit tool permissions:** every tool declares network, filesystem and effects. A tool with external effects must require approval (otherwise registration fails). Calls without an approval id are refused.                                                                                                                                                                                                                                                                                                                                                                                          | `packages/tools/src/{tool,registry}.ts`                                                    | `registry.test.ts`                                                                                       |
| **User approval for write actions:** the research workflow never approves itself and refuses tools with `requiresApproval` or external effects (`tool.refused`). The only writes are to the app's own database, plus the backup file, whose path the user chooses in a save dialog.                                                                                                                                                                                                                                                                                                                       | `research/workflow.ts`, `main/index.ts`                                                    | `lifecycle.test.ts` (approval guard)                                                                     |
| **Model-driven tools only through the ToolGateway (Phase 8.2):** off by default (`chat.webSearch`). When on, Chat only (Legacy, and ADK through RegistryTool in gateway mode); deny by default; only `web_search` (network-read, no approval) can be offered; strict argument/result validation; never an approval or task id; budgets enforced by the app (2 rounds, 3 calls, 1 identical, 5 results, 8 KB/24 KB, 60 s); results fenced as untrusted; cancellation first, late results discarded; diagnostics without query text. Research never gets tools; the shared provider keeps tool calling off. | `agent-runtime/src/tools/gateway.ts`, `chat/tool-chat.ts`, `agent-host/src/chat-engine.ts` | `gateway.test.ts`, `tool-chat.test.ts`, `chat-web-search.integration.test.ts`, `security-guards.test.ts` |
| **No shell execution:** no `child_process`, `spawn`, `exec` or `worker_threads` in shipped code; the agent and its tools start nothing. | **No arbitrary file deletion:** the only deletes remove the backup's own temporary file after a failed backup and the agent's own connection state file. | **No dynamic code evaluation:** no `eval`, `new Function` or `vm`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | —                                                                                          | `security-guards.test.ts`                                                                                |
| **No model downloads:** the app never calls Ollama's pull, push, create or delete endpoints. | **Untrusted web content:** page text, page titles and claims derived from pages appear in prompts only inside `<<<UNTRUSTED_WEB_CONTENT … UNTRUSTED_WEB_CONTENT>>>` blocks. | **Prompt-injection resistance by design:** model output is JSON validated with Zod. Tools are called by fixed workflow code, never by the model. | **No background downloads by Chromium:** the session spellchecker is disabled with no languages, so no Hunspell dictionaries are fetched from Google's CDN (`redirector.gvt1.com`); windows also set `spellcheck: false`.                                                                                                                                                                                                                                                                                                                                                                                 | `main/index.ts`, `main/window.ts`                                                          | `security-guards.test.ts`, `smoke:packaged` (Chromium net log of every run: no external host)            |

## Reporting a problem

Treat anything that lets web content or a model answer do more than "be text in a
report" as a security bug.
